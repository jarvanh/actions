## 为什么归档而不删除

这类长周期修复文档里有两类内容，价值不同：

| 类型 | 是否可删 | 例 |
|---|---|---|
| 执行过程（复选框、逐轮进度、某轮日志摘录） | 可删，但留着也无害 | 「run 36168731333 硬顶闸命中两次」 |
| **结论级判据**（踩过的坑、已定性的天花板、纪律） | **删了会重踩** | 「以列表为准的判据必须直读交叉验证」 |

判据散落在几千行过程记录里，删除等于丢掉。故整体移入本目录：
日常不用读，需要查"为什么这么写"时能找到出处。

## 从归档文档提炼出的常驻结论

已迁进 `README.md` 的 openlist 章节，日常看那里即可：

- **吞吐天花板**: 1.2 MiB/s，瓶颈是 runner→国内网盘的国际链路且多后端共享 ⇒ 工程外，勿再折腾
- **判据纪律**: 凡"以列表为准"的判据，都要用直读（stat/lsjson）交叉验证
- **硬顶闸纪律**: 可能长期不返回的代码，其内部必须有周期性硬顶复查，并把结果通过返回值传给调用方
- **还原语义**: copyto 保留备份副本；出账不可逆 ⇒ 副本/源端两侧判据都须双判据；真还原须过门禁
